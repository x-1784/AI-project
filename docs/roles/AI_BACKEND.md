## 4. API 契约建议

### 4.1 `/api/chat`

请求示例：

```json
{
  "messages": [
    { "role": "user", "content": "帮我整理这段文字" }
  ]
}
```

要求：

- 使用 Zod 校验；
- 限制消息数量、单条长度和总字符数；
- 只有服务端能读取模型配置；
- 流式返回；
- 客户端断开时停止上游请求；
- 错误使用稳定错误码。

### 4.2 错误码建议

| 错误码 | HTTP 状态 | 含义 | 前端行为 |
| --- | --- | --- | --- |
| `INVALID_REQUEST` | 400 | 请求格式/内容不合法 | 显示可读提示，不重试 |
| `AI_NOT_CONFIGURED` | 503 | 未配置 AI 密钥/模型 | 显示“AI 功能尚未配置” |
| `AI_UNAUTHORIZED` | 502 | 上游鉴权失败 | 显示服务不可用，记录服务端日志 |
| `AI_RATE_LIMITED` | 429 | 上游或本地限流 | 提示稍后重试 |
| `AI_TIMEOUT` | 504 | 上游超时 | 提供重试 |
| `AI_UNAVAILABLE` | 502 | 上游不可用/网络错误 | 提供重试 |
| `STREAM_ABORTED` | 499（内部约定） | 客户端主动取消 | 不显示错误，标记已停止 |
| `INTERNAL_ERROR` | 500 | 未分类服务端错误 | 通用错误提示 + 重试 |

前端根据错误码映射到当前语言，不直接展示 `message` 中的内部细节。

### 4.3 安全要求

- 密钥只存在于 `.env.local` 或部署平台；
- 禁止 `NEXT_PUBLIC_AI_*`；
- 不在日志中记录密钥、完整 prompt 或用户敏感内容；
- 不使用客户端传入的用户身份作为权限依据；
- 变更类接口校验来源和认证状态；
- 不执行未经授权的清库、删表、重置迁移等操作。

## 5. 技术建议

- AI SDK 的 `streamText` 等流式能力；
- provider 使用 OpenAI-compatible 配置，方便切换 DeepSeek、OpenAI、Qwen 等服务；
- Route Handler 使用 Node.js runtime（除非确认 Edge 兼容）；
- 根据部署平台设置合理的最大执行时间；
- 环境变量在服务端集中解析和校验；缺少变量时返回可诊断但不泄密的错误；
- 限流先做内存版，并明确它只在单实例内有效；多实例部署后再考虑 Redis/数据库；
- 为校验、错误映射、abort 行为写单元测试；
- 真实 AI 调用测试必须手动或使用受保护的集成测试开关，不在普通 CI 中消耗额度。

## 6. 验收标准

- 没有密钥时，站点仍可启动，UI 明确提示未配置；
- 真实调用时能收到流式内容；
- 停止生成能终止上游请求；
- 超时、限流、鉴权失败都有明确错误码和用户提示；
- 客户端拿不到任何密钥或内部堆栈；
- 所有输入经过服务端校验；
- 阶段 5 的用户数据隔离测试通过；
- 数据库迁移可重复执行且有文档；
- 不伪造 AI 输出或测试结果。

## 3. 首屏构图（桌面 ≥1280px）

### 3.1 栅格

12 列 / 容器 `1280px` / gutter `32px`。列宽 `(1280 − 32×11) / 12 ≈ 77.3px`。

| 元素 | 列位置 | 其他定位 |
| --- | --- | --- |
| 文字轴（eyebrow / 标题 / lead） | 列 1–5 | 垂直起点 `22vh`，左对齐 |
| AI 输入框 | 列 1–6 | 距标题 `48px`，略宽于文字轴形成"探出"感 |
| 快捷入口 | 列 1–7 | 首屏下沿 |
| 3D 核心 | 列 7–12 | 中心约 `(70%, 33%)`，**半径大到被顶部边界裁切** |
| 背景 | 全幅 | 极弱径向网格（不透明度 ≤0.03）+ 星尘 |

### 3.2 构图示意

```text
┌──────────────────────────────────────────────────────────────┐
│  ◇ NEBULA AI        首页  工作台  能力          中 / EN      │ 64px 导航
├──────────────────────────────────────────────────────────────┤
│                                          ╭──────────╮        │
│   把想法                                          │        │  ← 核心溢出上边界
│   发射出去                    核心中心 (70%, 33%)  │        │     被裁切
│                                          ╰──────────╯        │
│   一句话交给 NEBULA，                            ●           │
│   从构思到成稿。                                              │
│                                          ╭────╮              │
│   ┌────────────────────────────────┐     │轨道│             │
│   │ 描述你想创作的东西…         ↗ │     ╰────╯              │
│   └────────────────────────────────┘                         │
│   ⌘K 与 NEBULA 对话                                          │
│                                                              │
│   ──────────────────────────────────────────────             │
│   常用入口：写作 / 总结 / 代码 / 图像                         │
└──────────────────────────────────────────────────────────────┘
    ← 文字轴 列1-5 →   ←──── 核心 列7-12，重心偏右上 ────→
```

### 3.3 关键约束

- **边界裁切是这张构图的关键。** 完整悬浮在中央 = 3D 展示 demo；被边界裁切、部分"藏进画面外" = 它属于这个空间。这一条直接决定首页是"作品"还是"作业"。
- 层次（`z-index` 由下到上）：背景星尘 → 3D Canvas → 地平线光带 → 文字/标题 → 输入框（玻璃）→ 导航。
- 输入框压在核心前景，玻璃折射让两层产生物理关系，而不是各占一块地。
- 核心背后不得出现方形画布边界。`P2-3D-01` 的约束：核心直径只占画布高度 62%，宽幅柔光用 CSS 径向渐变而非画在 canvas 里。
- 光源方向统一在左上（与核心位置一致）。**当前 `body` 仍是双光源**（`15% -10%` 与 `90% 10%`），见第 10 节。

### 3.4 已冻结

非对称双轴 + 上边界裁切、文字轴左 40%、核心偏右上——用户已批准，不再讨论。

### 3.5 复用现有组件

首屏元素不新建基础组件，直接复用 `src/components/ui/`：

| 元素 | 组件 | 用法 |
| --- | --- | --- |
| eyebrow 小标签 | `Badge` | `tone="accent"`，文案 `Home.hero.eyebrow` |
| 标题 | `h1` + `nx-h1` 版式 | 两行，见 3.6 |
| AI 输入框 | `Textarea` | 多行，带发送按钮 |
| 发送按钮 | `Button` | `variant="primary"` `size="md"`，`aria-label` 用 `Home.hero.send` |
| 快捷入口 | `Button` | `variant="ghost"` `size="sm"` |
| 输入框容器 | `Panel` | `tone="glass"` `padding="sm"` |

### 3.6 字距与字号

首屏标题走 `nx-h1` 版式阶梯（`clamp(36px, 4.4vw, 56px)`，`line-height 1.06`，`letter-spacing -0.02em`）。

中文必须归零字距并抬高行高，否则双语切换时中文会挤成一团：

```css
:lang(zh-CN) .nx-h1 {
  letter-spacing: 0;
  line-height: 1.1;
}
```

> 该版式类目前**尚未落地**在 `globals.css`（#27 只收了组件当前用到的尺寸 token）。需要在 `P2-HOME-02` 实现首屏时补上，或提前在 #17 一并加。见第 10 节。

## 4. 能力展示区（本区块的核心难点）

任务卡明确验收：**不是"居中标题 + 三张同构卡片"**。四张等高卡片同样被排除。

### 4.1 方案：不对称双列 + 一条横向流程带

```text
┌──────────────────────────────────────────────────────────────┐
│  能力                                            01 — 04     │
│  不是四个功能，是一条流水线                                   │
│                                                              │
│  ┌───────────────────────────┐  ┌──────────────────────┐    │
│  │                           │  │  02  总结            │    │
│  │  01  写作                 │  ├──────────────────────┤    │
│  │  从一句模糊的想法到        │  │  03  代码            │    │
│  │  可以发布的成稿。          │  ├──────────────────────┤    │
│  │  （7 列宽，双倍高）        │  │  04  图像            │    │
│  └───────────────────────────┘  └──────────────────────┘    │
│                                                              │
│  ── 构思 ──────────── 生成 ──────────── 打磨 ──────────── 定稿 ──│
└──────────────────────────────────────────────────────────────┘
```

- 左侧一张 **7 列宽、双倍高**的主能力卡（`Panel` `tone="glass"` `padding="lg"`）；
- 右侧 **5 列**分三张等高小卡（`Panel` `tone="solid"` `padding="md"`，视觉降级）；
- 底部一条 4 段横向流程带，用 `border-nx-line-hair` 连接，**不用箭头图标**。

### 4.2 为什么这样排

- 四张同构卡片的本质问题是**没有信息层级**，观众无法判断哪个最重要；
- 写作是主场景，给它 7 列 + 双倍高，其余三项降级为索引式列表，层级立刻成立；
- 流程带承担"这不是功能清单，是一条链路"的叙事，比再加第五张卡有效。

## 5. 工作台预览区

展示产品真实形态，但不能造假——**必须标注为预览**（`CLAUDE.md` §3.3 真实性与错误状态）。

- 构图：一块略微倾斜（约 `-1.2deg`）的玻璃面板，宽 10 列，居中偏右，**溢出右侧容器边界**；
- 面板内是示意性 UI：左侧会话列表骨架、右侧消息气泡与流式打字态；
- 面板左上角 `Badge` `tone="muted"`：`界面预览 · 非真实数据`；
- 面板下方一行短说明，不超过 24 字。

倾斜 + 溢出是刻意的：它暗示"这是一个可以进去的空间"；正放的截图框会读成"产品截图"。

无障碍：面板需 `aria-label`，且内部骨架元素标记 `aria-hidden`，避免屏幕阅读器朗读占位文本。

## 6. 品牌宣言区与收尾

### 6.1 宣言

- 左侧 8 列：一句大字宣言，用 `nx-h2`（`clamp(28px, 3vw, 38px)`），**不用 display 级字号**，避免与首屏抢焦点；
- 右侧 4 列：三行态度短句，`text-ui`，色 `text-nx-ink-3`；
- 背景降到 `--nx-deep`，与上方区分。

### 6.2 收尾 CTA

- 居中单列，最大 6 列宽；
- 一句短文案 + 一个 `Button` `variant="primary"` `size="lg"`，点击回到首屏输入框；
- 跳转用锚点（`#composer`），**不用 JS 滚动劫持**；
- 背景回到 `--nx-void`，让 3D 余晖自然收束。

### 7.1 平板（768–1024px）

- 工作台预览倾斜角收到 `-0.6deg`，溢出取消。

### 7.2 手机（<768px）

```text
┌──────────────────────┐
│  ◇ NEBULA      ☰ 中  │
├──────────────────────┤
│        ╭────╮        │  ← 核心 min(62vw, 260px)
│        ╰────╯        │     独立占位，约 34vh
│                      │
│  把想法发射出去        │  ← 标题在核心下方
│  一句话交给 NEBULA…   │
│                      │
│  ┌────────────────┐  │
│  │ 描述你想创作…  ↗│  │
│  └────────────────┘  │
└──────────────────────┘
```

**核心不能压在文字下面。** 手机屏小，核心若作背景会直接吃掉正文可读性（违反"层次与距离"前提）。因此改为上下结构：核心独立占一个视觉块，标题下锚。

手机端：粒子 800、DPR 上限 1.25（见 `P2-3D-01` 降级档）；能力区改为单列，主卡在首、三张小卡顺次堆叠；工作台预览不倾斜、不溢出。

## 8. 首屏加载顺序（避免白屏/闪黑）

1. 首帧立刻渲染 CSS 静态核心轮廓（同心径向渐变 + 少量星点），形状与色调与 3D 一致；
2. 导航与文字直接服务端渲染，不等待 3D；
3. 3D chunk 加载完成 → 核心在 `320ms` 内淡入并替换静态轮廓，静态层淡出；
4. 若 3D 加载失败或 WebGL 不可用 → 静态层**保持不动**，用户不会看到任何跳变。

这把"降级"变成默认外观的一部分，而不是出错才补的兜底。

## 0. 先读这一节

NEBULA AI 不是课程作业、静态展示页或套了深色主题的聊天机器人。我们要做的是一个**有视觉竞争力、有真实数据流、可以持续迭代并最终部署上线**的全栈 AI 创作平台。

当前状态：

- 项目已通过**阶段 1：基础设施**正式验收，当前处于**阶段 2：首页与视觉原型**；
- 阶段 2 计划已合入 `dev`（最新 `2be2a69`）；总追踪 Issue #22 和子 Issue #11–#21、#24 已创建；
- CI `quality` 已通过；
- 数据库与真实 AI 服务尚未接入；
- 任何 AI 在开始编码前，必须先阅读本文件、`TEAM_PLAYBOOK.md`、`AI_ONBOARDING.md`、自己的角色文档和根目录 `CLAUDE.md`。

工作原则：

1. 先理解，再行动；
2. 一次只推进一个阶段或一个明确任务；
3. 先做可运行、可验证的成果；
4. 不伪造 AI 输出、不伪造测试结果、不伪造完成状态；
5. 不一次性生成整个项目。

## 1. 项目定位

**NEBULA AI — AI Creative Universe**

一个将 AI 对话、创意生成、知识处理和个人工作空间融合在一起的沉浸式 AI 创作平台。

我们希望用户产生这样的感受：

- 进入一个具有未来科技感的 AI 创意空间；
- AI 不只是回答问题，而是帮助用户思考、学习、创作和完成任务；
- 不同能力像同一个 AI 宇宙中的不同工作区域，而不是互不相关的工具集合；
- 界面具有独特的品牌识别度，值得展示、体验和持续使用。

产品必须同时满足两个目标：

- **视觉表现力**：第一眼足够惊艳，有鲜明的设计语言、沉浸式 3D 场景和精致的交互细节；
- **真实可用性**：页面不是摆设，用户能完成实际操作，AI 功能有真实的数据流和后端逻辑，错误状态明确，数据能合理保存。

## 2. 品牌与视觉方向

### 2.1 整体风格

- 主风格：未来主义、深空美学、沉浸式数字宇宙；
- 背景：黑曜石黑、深空黑、深蓝黑；
- 强调色：电光蓝、星云紫，少量使用冷色渐变；
- 材质：精致玻璃质感、半透明面板、柔和辉光、细腻边框；
- 背景细节：适量星尘、粒子、微弱光线和空间深度；
- 排版：有高级感的中英文字体组合，明确的标题层级、留白和视觉节奏；
- 动效：自然、克制、流畅，强调空间感与交互反馈；
- 图标：统一使用 `lucide-react`，不混用风格不一致的图标。

不要把所有元素都做成发光玻璃卡片。视觉必须有主次、留白、层次和节奏，避免廉价的赛博朋克效果。

### 2.2 核心视觉：3D 能量核心

首页必须有一个具有品牌识别度的实时 3D 能量核心：

- 悬浮于深空中的球形能量体；
- 表面有流动光带、能量纹理、粒子或星云效果；
- 蓝紫渐变、体积感、深度感和细腻光照；
- 随时间缓慢旋转、呼吸或发生细微变化；
- 鼠标移动时产生适度的视差或视线响应；
- 用户交互时有自然的能量反馈；
- 与页面文字、背景和其他 UI 元素融为一体，而不是孤立地放在页面中央；
- 动画流畅，不能影响输入、滚动和其他主要交互。

**必须使用真正的实时 3D 技术，不能用静态图片假装 3D。**

### 2.3 动效原则

- 首次进入页面有轻量级入场动画；
- 标题、文字、导航和功能区域有合理的出现节奏；
- 按钮有精致的 hover、active、focus 状态；
- 卡片有适度的深度、边框和悬停反馈；
- 页面滚动产生克制的空间层次变化；
- 页面切换和弹窗出现、关闭流畅自然；
- AI 请求期间提供明确的加载、流式输出和停止操作反馈；
- 避免无意义动画、夸张缩放、持续闪烁和强制等待。

## 3. 国际化：不可妥协的基础要求

支持两种语言：

- 简体中文：`zh-CN`
- 英文：`en`

硬性规则：

1. **默认语言必须是简体中文**，不能因为浏览器或操作系统语言是英文而改变默认行为。
2. 用户首次访问根路径 `/` 时进入中文界面。
3. 提供清晰的语言切换入口，例如导航栏中的 `中文 / EN`。
4. 切换语言后当前页面内容立即更新，不需要手动刷新。
5. 切换语言时尽可能保留当前页面、查询参数、输入内容和交互状态。
6. 记住用户主动选择的语言，并在后续访问时合理恢复。
7. 所有用户可见文字统一管理在语言资源文件中。
8. 严禁在大量组件中直接硬编码中文或英文。
9. 导航、表单、按钮、提示、错误信息、加载状态、空状态、弹窗、设置页、AI 工作台都支持双语。
10. 页面标题、描述、无障碍标签、SEO 元数据也支持双语。
11. 日期、时间、数字根据当前语言格式化。
12. 注意中英文文字长度差异，避免溢出、错位和布局异常。

技术方向：

- 使用 `next-intl`；
- 路由建议为 `/zh-CN/...` 与 `/en/...`；
- 默认 locale 为 `zh-CN`；
- 关闭基于 `Accept-Language` 的自动语言检测；
- 用户显式切换后写入 `NEXT_LOCALE` Cookie；
- 非法 locale 返回 404，不得静默渲染。

## 4. 功能范围

### 4.1 首页（阶段 2 重点）

必须包含：

- 品牌 Logo 与 NEBULA AI 名称；
- 清晰的导航栏；
- 中英文切换入口；
- 醒目的主标题与产品价值说明；
- 核心 3D 能量球；
- AI 输入框或创作入口；
- 常用任务快捷入口；
- 主要 AI 能力的介绍；
- 有层次的功能展示区域；
- 适当的品牌介绍、页脚和辅助信息。

首页不采用“居中标题 + 三张同构卡片”的模板。应采用有编辑感的不对称构图：文字、3D 核心、输入框和背景共同形成空间纵深。

### 4.2 AI 对话工作台（阶段 3–4）

- 多轮对话；
- 用户消息与 AI 消息清晰区分；
- 流式输出；
- Markdown 内容渲染；
- 代码块展示与复制；
- 复制回答；
- 停止生成；
- 重新生成或继续对话；
- 新建对话；
- 对话列表和历史记录；
- 加载状态、失败提示、重试机制；
- 空白状态与首次使用引导。

不能只做外观像聊天窗口的静态页面。后端接入后必须能够实际调用 AI 服务。

### 4.3 AI 创作与工具（后续阶段）

逐步扩展：

- AI 对话；
- 文档上传与内容理解；
- 图像创作入口；
- 长文本整理、总结和改写；
- 创作项目管理；
- 历史作品与任务记录。

如果模型或服务暂不支持某项能力，不得伪装成已经完成。可以先开发真实可交互的 UI 原型，但必须明确标注“演示模式/未接入真实服务”。

### 4.4 用户与个人空间（阶段 5）

- 用户注册、登录和退出；
- 个人设置；
- 语言偏好；
- 对话和创作历史；
- 文件管理；
- 用户数据隔离；
- 基础账号安全和权限控制。

身份认证、文件上传和数据持久化必须建立在合理的服务端权限检查上，不能只靠前端隐藏按钮。

- pnpm；
- Tailwind CSS v4 + CSS 设计变量；
- shadcn/ui（按需引入）；

- 清晰的模块化结构；

- 避免所有逻辑都写在单个页面或巨型组件中；
- 使用类型系统减少运行时错误；
- 不引入没有实际价值的依赖；
- 不为复杂而复杂；
- 明确区分服务端和客户端代码；
- 所有敏感密钥只能在服务端使用，绝不能暴露到浏览器；

## 6. AI 服务要求

- 在服务端统一封装 AI 调用；
- 支持配置模型提供商、模型名称和 API 地址；
- API 密钥只存放在环境变量中；
- 浏览器不能直接获取或暴露密钥；
- 提供流式响应；
- 正确处理请求失败、超时、限流和用户取消请求；
- 对用户输入进行必要验证；
- 错误信息不向普通用户暴露内部堆栈、密钥或敏感配置；
- AI 服务不可用时提供友好提示；
- 没有配置 API 密钥时，网站仍能启动并展示基础界面，但明确提示 AI 功能尚未配置；
- 不得将固定写死的回答伪装成真实模型输出；
- 根据实际服务能力处理上下文限制和响应异常。

建议环境变量：

```dotenv
AI_API_KEY=
AI_BASE_URL=
AI_MODEL=
AI_TIMEOUT_MS=60000
AI_MAX_OUTPUT_TOKENS=
```

错误响应应使用稳定错误码，例如：

```json
{ "error": { "code": "AI_NOT_CONFIGURED", "message": "safe internal message" } }
```

前端根据错误码映射到当前语言的用户提示，不直接展示上游原始错误。

## 7. 数据库与数据持久化（阶段 5）

不在第一阶段急于引入数据库。等功能和数据模型明确后再建立持久化方案。

最终需要合理支持：

- 用户信息；
- 对话会话；
- 消息记录；
- 创作任务与作品；
- 文件元数据；
- 用户语言偏好；
- 必要的创建时间、更新时间和状态字段。

要求：

- 根据真实业务设计表结构与关联关系；
- 建立合理的索引与约束；
- 设计数据库迁移流程；
- 敏感配置通过环境变量管理；
- 提供 `.env.example`，只能包含变量名和占位示例；
- 不擅自清空、覆盖或修改已有重要数据；
- 数据查询和修改必须校验当前用户的权限。

## 8. 性能、响应式与可访问性

### 8.1 性能

- 合理控制 3D 模型复杂度、粒子数量和渲染分辨率；
- 优先优化首屏加载；
- 对非首屏模块和较重的 3D 场景采用延迟加载；
- 防止不必要的 React 重渲染；
- 避免重复创建 WebGL 渲染器、几何体和材质；
- 正确清理动画、事件监听和 3D 资源；
- 关注 WebGL 不可用、设备性能不足和显存限制；
- 为低性能设备提供简化模式；
- 避免未压缩的大图片、过大的依赖和无必要的网络请求。

### 8.2 响应式

至少兼顾：

- 桌面端；
- 笔记本电脑；
- 平板；
- 手机。

桌面端重点展现沉浸式 3D 体验；移动端保证布局合理、文本可读、交互可用，并根据性能和屏幕尺寸调整 3D 效果。

### 8.3 可访问性

- 交互元素有清晰的焦点状态；
- 按钮和输入框有合理的可访问标签；
- 颜色对比度足够；
- 尊重减少动态效果的系统偏好；
- 不依赖颜色或动画作为唯一的信息表达方式。

---

## 9. 安全与工程质量

- 不得将 API 密钥、数据库密码或其他秘密写入源代码；
- 不得将服务端密钥暴露到 `NEXT_PUBLIC_` 等客户端公开变量中；
- 对输入、文件上传、权限和请求参数进行合理验证；
- 防止未授权访问其他用户的数据；
- 关注 XSS、CSRF、注入和文件上传风险；
- 不在浏览器端保存不适合暴露的敏感信息；
- 不擅自执行删除项目、覆盖文件、重置数据库或修改系统配置等破坏性操作；
- 重要业务逻辑应有适当测试；
- 不以“代码已生成”作为功能完成的证明。

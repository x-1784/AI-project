## 4. 发现

### 4.1 PR #30（#18 布局集成）

**P1-1 容器宽度未 token 化，且使用了与内置类等价的 arbitrary value**

- 位置：`error.tsx:14`、`loading.tsx:10`、`not-found.tsx:9`、`page.tsx:53`、`site-footer.tsx:8`、`site-header.tsx:12`
- 事实：`max-w-[80rem]` 与 Tailwind 内置 `max-w-7xl`（`--container-7xl: 80rem`）完全等价
- 影响：同一宽度在 6 个文件重复书写，且不在 `DESIGN_TOKENS.md` 的 token 体系内。#15 铺首页区块后会扩散到 10 处以上，改容器宽度需全局搜索替换
- 建议：改用 `max-w-7xl`；如需语义化，在 `globals.css` 增加 `--container-nx: 80rem`，统一为 `max-w-nx`

**P1-2 修改了他人负责的目录，未见所有权协调记录**

- 位置：`src/app/[locale]/page.tsx:53`
- 事实：`.github/CODEOWNERS` 中 `/src/app/*/page.tsx` 归属 `@BJSH-1`；本 PR 实际改动该文件
- 影响：违反 `PHASE2_PLAN.md` §8.5「不修改别人负责的目录而不协调」
- 建议：改动本身无害（仅容器类名），但需 @BJSH-1 知情确认；或在 PR 描述中显式列出跨所有权文件

**P2-1 `scroll-mt-16` 与 header 实际高度差 1px**

- 位置：`layout.tsx:50-55`
- 事实：`scroll-mt-16` = 64px；header 为 `h-16`(64px) + `border-b`(1px) = 65px
- 影响：skip link 跳转后主内容顶端被 header 下边框压住 1px，视觉上贴边
- 建议：改 `scroll-mt-[4.0625rem]`，或给 header 用 `border-b` 的同时把高度写成 `h-[calc(4rem+1px)]`

**P2-2 字号 token 体系分裂**

- 位置：`site-header.tsx:12`、`site-footer.tsx:8` 用 `text-sm`（14px）；`page.tsx:64` 用 `text-base` / `sm:text-lg`
- 事实：`globals.css` 已定义 `--text-ui: 14px`、`--text-body: 16px`，当前值与 `text-sm` / `text-base` 相同但语义不同
- 影响：后续调整 token 时，用 `text-sm` 的地方不会跟随
- 建议：布局层统一 `text-ui`；`page.tsx` 字号体系归 #15，本 PR 可不改

**P2-3 四处 arbitrary 值未收进 token**

- 位置：`page.tsx:54`（`text-[0.7rem]`、`tracking-[0.2em]`）、`not-found.tsx:11`（`tracking-[0.3em]`）、`site-header.tsx:15`（`tracking-[0.28em]`）
- 事实：`--tracking-nx-caption: 0.12em` 已存在但未被使用，同时存在 3 种手写 em 值
- 建议：扩展 `--tracking-nx-*` 三档并替换；`text-[0.7rem]` 改用 `text-caption`

**P2-4 渐变颜色未引用 token**

- 位置：`globals.css` body 背景
- 事实：`rgba(75, 140, 255, 0.16)` 与 `--nx-electric #4b8cff` 数值一致，但写成了字面量；新增注释只说明「单光源」，未说明颜色对齐

**P2-5 验证表缺少断点边界区间**

**P3-1 `body` 的 `background` shorthand 与 utility 并存**

### 4.2 PR #27（#17 UI 基础组件，回溯）

**P1-3 `cn()` 只拼接不合并冲突类，调用方 `className` 无法可靠覆盖变体**

- 位置：`src/lib/utils/cn.ts:9-11`；受影响：`panel.tsx:19-24`、`button.tsx:63-72`
- 事实：`cn` 仅做 `filter(Boolean).join(" ")`。构建产物显示 `.p-4`(10704) < `.p-6`(10742) < `.p-8`(10780)，同属性工具类按数值升序输出
- 影响：`<Panel padding="md" className="p-0">` 会同时输出 `p-6 p-0`，而 `.p-6` 在 CSS 中更靠后，**`p-0` 失效**。`Panel` 暴露了 `padding` prop 又允许 `className`，两者冲突时行为不符合直觉
- 建议：引入 `tailwind-merge`（约 7KB gzip）替换 `cn` 实现；或在文档中明确「不得用 `className` 覆盖内距类」，并为 `Panel` 增加 `padding="none"` 的显式用法引导

**P1-4 `isLoading` 不拦截表单回车提交路径**

- 位置：`button.tsx:56-62`
- 事实：`isLoading` 时不设原生 `disabled`，依靠 `pointer-events-none`（鼠标）+ `onClick` 内 `preventDefault`（鼠标/键盘触发按钮本身）拦截
- 影响：当 `type="submit"` 时，用户在输入框内按 Enter 触发表单提交，**不经过按钮的 `onClick`**，`isLoading` 期间仍会重复提交。阶段 3 聊天输入框是 `Enter` 发送，该路径必然被触发
- 建议：在表单层用 `useFormStatus` 判断 pending 并阻止 `onSubmit`；或让 `isLoading` 同时设原生 `disabled`（代价是失去焦点保持，需原作者权衡）

**P2-6 Input / Textarea 无错误态**

- 位置：`input.tsx:24-37`、`textarea.tsx:33-46`
- 事实：只有 `hint`（`aria-describedby`），无 `aria-invalid`、无错误信息容器、无 `role="alert"`
- 影响：阶段 3 需要展示「超过长度上限」「请求失败」等输入错误
- 建议：增加 `error?: ReactNode`，输出 `aria-invalid` + 错误节点 id 并入 `aria-describedby`

**P2-7 Textarea 长度上限未与服务端契约联动**

- 位置：`textarea.tsx`
- 事实：无默认 `maxLength`；`src/lib/ai/contracts.ts` 中 `CHAT_LIMITS.maxMessageChars = 8000` 是服务端唯一权威
- 影响：用户可输入超限内容，提交后被服务端以 `INVALID_REQUEST 400` 拒绝，体验割裂
- 建议：阶段 3 在聊天输入处 `maxLength={CHAT_LIMITS.maxMessageChars}`，并在接近上限时提示

**P2-8 `forwardRef` 属 React 19 技术债**

- 位置：`button.tsx:32`
- 事实：项目 React 19.3.0，`ref` 已可作为普通 prop 传递，`forwardRef` 不再是必需
- 建议：非阻塞；下次改动 Button 时顺带迁移

**P2-9 Input / Textarea 的 `"use client"` 可能不必要**

- 位置：`input.tsx:1`、`textarea.tsx:1`
- 事实：两个组件只使用 `useId`（RSC 中可用），自身不持状态、不注册浏览器副作用
- 影响：标记后，即使在纯静态表单页也会被拉入客户端包；当前影响很小，组件增多后累积
- 建议：确认为受控输入时由调用方的 client 边界承担；否则移除标记，由实测决定

**P3-2 预览页未入库，视觉验收不可复现**

- 位置：`docs/design/ui-primitives/README.md:8-9`
- 事实：README 说明预览页使用临时路由 `/zh-CN/ui-preview` 且未提交
- 建议：后续可把预览页收进 `src/app/[locale]/(dev)/ui-preview` 并用环境变量在生产关闭，便于回归

## 6. 对比度计算脚本

```python
def srgb(c):
    c = c / 255
    return c / 12.92 if c <= 0.04045 else ((c + 0.055) / 1.055) ** 2.4

def lum(hex_color):
    h = hex_color.lstrip("#")
    r, g, b = (int(h[i:i + 2], 16) for i in (0, 2, 4))
    return 0.2126 * srgb(r) + 0.7152 * srgb(g) + 0.0722 * srgb(b)

def contrast(a, b):
    la, lb = lum(a), lum(b)
    hi, lo = max(la, lb), min(la, lb)
    return (hi + 0.05) / (lo + 0.05)
```
